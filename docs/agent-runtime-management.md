# Agent 运行时管理中心

本文档记录 CoilCoil 主工作区的“技能”入口与右侧 Agent 运行时管理中心需求。目标不是再做一个设置页，而是让用户在当前会话中看见并控制真正生效的 Agent 上下文、技能、MCP 和项目记忆。

## 1. 主工作区技能入口

左侧主导航在“新建对话”下增加“技能”。

- 点击“技能”时保留左侧 Workspace 与会话列表。
- 中间聊天区域和右侧栏合并为技能工作区，展示现有 `SkillSettings` 内容。
- 设置页中的“技能”栏目继续保留；两个入口复用同一个组件、Runtime 命令和数据源，不能形成两套配置。
- 点击任意会话、创建新对话或返回对话时退出技能工作区。
- 主工作区和设置页统一使用中文名称“技能”，内部代码仍可使用 `skills`。

## 2. 设置页返回入口

- 设置页左上角原 CoilCoil 品牌位置改为“返回工作区”。
- 移除左下角重复的返回按钮。
- 返回按钮需要避开 macOS 红绿灯并保持可拖动标题栏区域。
- 从设置页返回聊天时，当前会话默认回到最新消息位置，不能跳到聊天顶部。

## 3. 右侧栏信息架构

右侧栏保留现有“文件”，新增“运行时”视图。项目记忆先作为“运行时”内的一个分区，不单独占用一级 Tab；如果后续记忆能力明显扩展，再评估独立视图。

```text
右侧栏
├── 文件
└── 运行时
    ├── 上下文与 Token
    ├── System Prompt
    ├── 会话内容明细
    ├── 技能
    ├── MCP
    └── 项目记忆
```

## 4. 上下文与 Token

### 总览

至少展示当前会话真正生效的数据：

- 当前上下文占用与模型上下文上限
- 累计输入 Token
- 累计输出 Token
- 缓存写入与缓存读取 Token（供应商返回时）
- 当前请求输出 Token
- System Prompt 的 Token 占用
- 工具定义的 Token 占用
- 对话消息和工具结果的 Token 占用

没有上游数据的字段隐藏，不显示虚假的 `0` 或破折号。精确值和本地估算值必须明确区分；不得把字符数伪装成 Token 数。

### 缓存命中率

- 只有供应商提供缓存读取字段时才展示。
- Runtime 先把不同供应商 usage 归一化，再计算命中率。
- 界面必须说明分母口径。默认优先使用“缓存读取 Token / 可缓存输入 Token”；若某供应商的 input 已包含缓存部分，则按该供应商语义归一化后计算。
- 缓存字段只用于上下文/成本说明，不参与首字延迟与输出速度评级。

## 5. 有效 System Prompt

- 展示当前请求最终发送给模型的有效 System Prompt，而不是某个静态模板文件。
- 显示总 Token，并允许按来源查看：Pi 核心提示、CoilCoil 工作流、项目说明、记忆、技能和其他扩展注入。
- 支持会话级临时编辑，但必须保留“恢复默认”入口，并清楚提示这会改变后续请求、可能降低提示缓存命中率。
- 临时编辑不得反向覆盖扩展源码或全局设置；持久修改仍应进入对应配置页。

## 6. 会话内容明细与精简

用户需要按真实上下文顺序查看：

- 每条用户 Prompt
- 每轮 Assistant 文本与 reasoning
- 每次工具调用的参数、结果和 Token 占用
- MCP 工具结果
- 子 Agent 汇总或注入回主会话的内容

可选择移除历史工具结果或消息，以减少后续上下文。该能力属于 Runtime 数据修改，不是 UI 隐藏：

1. 必须确认 Pi 当前 Session 的可编辑/回溯能力和持久化格式。
2. 删除前展示影响范围和预计释放 Token。
3. 操作需要确认，并提供本次会话内的撤销或安全快照。
4. 不得修改磁盘工作区，也不能声称会回滚 Agent 已修改的文件。
5. 若 Pi 不支持安全的原位修改，采用“从选定上下文生成精简会话”的方式，不直接破坏原始会话记录。

第一阶段只做可观测视图；修改上下文必须在 Session 变换协议和恢复测试完成后开放。

## 6.1 Pi 总结与上下文压缩事件

右侧“运行时”必须把 Pi 原生总结作为一等事件展示，不能只在 Token 总数中静默合并。

Pi 当前存在两类不同总结：

- `compaction`：上下文接近阈值、发生溢出恢复或用户手动 `/compact` 时，把较早内容压缩成总结并保留较新的尾部上下文。
- `branch_summary`：通过会话树切换到另一条路径时，可选地总结被离开的分支。

每个总结卡至少展示：

- 类型：自动压缩、溢出恢复、手动压缩或分支总结
- 开始、重试、完成、失败、已取消状态
- 触发时间与触发原因
- 压缩前 Token、压缩后估算 Token、预计释放 Token
- 生成总结本身消耗的 input/output/cache usage 与成本（上游提供时）
- 总结正文，可折叠查看
- 保留上下文的起点或 retained tail 概要
- Pi 默认总结记录的已读文件、已修改文件等 details
- 该总结是否位于当前活动分支、是否正在参与下一次模型请求

Runtime 直接订阅 Pi 的 `compaction_start`、`compaction_end` 和 summarization retry 事件，并从 SessionManager 的 `compaction` / `branch_summary` 条目恢复历史。重新打开应用后不能只显示本次进程产生的事件。

总结事件分为两个视角：

1. **当前上下文**：只展示当前活动分支上实际生效的总结，并计入上下文组成。
2. **会话历史**：允许查看其他分支上曾发生的总结，但明确标记“非当前分支”，不计入当前上下文与 Token。

## 6.2 回溯后的运行时一致性

CoilCoil 当前的历史消息编辑通过 Pi `navigateTree(entryId, { summarize: false })` 回到目标位置，然后从那里继续。这种操作会改变同一 Session 文件的活动叶节点，但不会自动生成离开分支的 `branch_summary`。

用户确认回溯时，右侧运行时面板必须和聊天时间线在同一个原子状态更新中完成：

1. 显示“正在切换上下文”，暂停对旧快照的交互操作。
2. Pi 导航完成后取得新的 `activeLeafId`、活动分支 entries 和有效模型上下文。
3. 立即移除不在新活动分支上的消息、工具结果和 compaction 对当前上下文的贡献；它们仍可留在“会话历史”中。
4. 重新计算 System Prompt、上下文占用、消息/工具 Token、缓存统计、技能、MCP 与 Memory 注入状态。
5. 发布带递增 `sessionRevision` 的完整运行时快照，再开始发送编辑后的 Prompt。
6. 后续每个增量事件都携带同一个 revision；前端丢弃来自旧分支或旧 revision 的迟到事件。

不能等新回复结束后才刷新右侧栏，也不能让旧分支的总结、工具 Token 或 MCP 状态短暂残留。回溯只改变会话上下文，不恢复磁盘文件，这一提示继续保留。

如果未来允许用户选择“总结离开的分支”，则显式调用 Pi 的 branch summarization，并把生成过程展示为独立事件；不能把当前 `summarize: false` 的线性回溯悄悄改成会产生额外模型请求的行为。

## 7. 会话级技能管理

- 列出当前会话可用的技能、来源、启用状态和本次是否已注入。
- 用户可为当前会话启用或停用技能。
- 必须区分：
  - 全局/项目发现与启停：由现有技能设置管理。
  - 当前会话选择：只改变当前 Session 后续请求，不应意外影响其他并行会话。
- 点击技能可查看名称、说明、来源、`SKILL.md` 路径和预计/实际注入 Token。
- 真正的技能加载继续走 Pi ResourceLoader/扩展机制，前端只消费结构化状态。

## 8. 会话级 MCP 管理

- 列出当前工作区可用的 MCP Server、连接状态、工具数和资源数。
- 支持在当前会话中启用/停用，以及连接、断开或重连。
- 配置编辑仍保留在设置页；运行时面板只提供高频开关和状态。
- 继续复用内置 `pi-mcp-adapter`，不实现第二套 MCP 协议或连接器。
- 必须定义全局/项目配置、Server 连接状态和当前会话工具暴露三层状态，避免“停用当前会话”误伤其他并行会话。

## 9. 项目记忆可视化

继续复用内置 `project-memory` Pi 扩展，在运行时面板展示：

- 当前项目记忆是否存在、文件位置、更新时间和大致 Token
- 后台整理状态：等待、运行、完成、失败
- 已纳入整理的会话和最近一次整理结果
- 当前会话是否已经注入项目记忆
- “立即整理”操作，对应现有 `/memory` 能力
- 最近错误、运行耗时和安全的重试入口

面板不能直接另写一套总结逻辑。若扩展尚未暴露上述状态，优先为扩展增加稳定的 headless 状态事件与命令。

## 10. Runtime 协议前置

在实现右侧“运行时”视图前，先定义并测试以下 typed protocol：

- `get_runtime_inspection`：有效 Prompt、上下文组成、usage 与各来源 Token
- `set_session_skill_state`：当前 Session 的技能开关
- `set_session_mcp_state`：当前 Session 的 MCP 暴露与连接意图
- `compact_session_context`：带预览、确认和结果的上下文精简
- `get_memory_status` / `run_memory_now`：项目记忆状态与手动整理
- `RuntimeSummaryEvent`：compaction/branch summary 的生命周期、usage、details 与活动分支状态
- `RuntimeInspectionSnapshot.sessionRevision` / `activeLeafId`：保证回溯前后的快照和增量事件不会串线
- 对应的增量事件，保证模型每轮请求、工具调用、MCP 状态和 memory worker 状态实时更新

所有命令必须携带 `runtimeId`/Session 作用域，保证多个并行会话互不影响。

## 11. 分阶段交付

1. 主导航技能入口、设置页返回入口和聊天滚动恢复。
2. 运行时只读总览：usage、上下文、有效 Prompt、技能/MCP/Memory 状态。
3. 会话级技能和 MCP 开关。
4. System Prompt 临时覆盖与恢复默认。
5. 上下文精简预览、确认、快照和恢复。

每一阶段都需要覆盖历史会话恢复、并行会话隔离、应用重启、不同 Provider usage 字段缺失和极窄右侧栏。

额外回归：包含多次 compaction 的长会话回溯到压缩前、压缩后以及另一分支，右侧“当前上下文”必须始终和 Pi `buildContextEntries()` 的活动分支一致。
